# Agent Guidelines for SptItemCreator

This document provides instructions for AI agents working on the SptItemCreator project, an SPT‑Aki mod for Escape from Tarkov.

## Project Overview

- **Language**: C# (.NET 9.0)
- **Project type**: ASP.NET Core Web SDK (output: Library)
- **Solution**: `SptItemCreator.sln`
- **Main project**: `SptItemCreator/SptItemCreator.csproj`
- **Dependencies**: SPTarkov.Common, SPTarkov.DI, SPTarkov.Server.Core, SPTarkov.Server.Web
- **External DLL**: `libs/SuntionCore.dll`

## Build and Testing Guidelines

**重要：Agent禁止执行任何构建、清理与测试操作。**

Agent应专注于代码编写和修改任务。完成代码生产后，必须告知用户，由用户自行执行构建、清理和测试操作。

## Code Style Guidelines

### Naming Conventions
- **PascalCase**: namespaces, classes, methods, properties, public fields, enums, events.
- **camelCase**: local variables, parameters, private fields.
- **Prefix interfaces with `I`**: `IOnLoad`, `IService`.
- **Use meaningful, descriptive names**; avoid abbreviations unless widely understood.

### File Organization
- One class per file (except nested classes).
- File name matches the class name.
- Place files in directories that reflect the namespace (e.g., `Core/Services/DataLoader.cs` → `SptItemCreator.Core.Services`).

### Imports (`using`)
- Group usings in the following order (separated by a blank line):
  1. `System.*`
  2. Third‑party libraries (e.g., `JetBrains.Annotations`, `SPTarkov.*`)
  3. Project‑internal namespaces (e.g., `SptItemCreator.Core.*`)
- Sort each group alphabetically.
- Remove unused `using` statements.

### Types and Variables
- Prefer `var` for local variables when the type is obvious from the right‑hand side.
- Use explicit types when clarity is needed (e.g., `List<string> items = new();`).
- Mark fields as `readonly` whenever possible.
- Use `sealed` classes unless inheritance is intended.

### Properties and Fields
- Use auto‑properties unless additional logic is required.
- Public fields are allowed for simple data carriers (e.g., DTOs) but prefer properties.
- Use expression‑body members for trivial getters/setters.

### Error Handling
- Use `try`‑`catch` blocks for expected exceptions.
- Log all exceptions with `LocalLog.Logger` (available via `LocalLog.Logger.Error`, `.Warn`, `.Info`, `.Debug`).
- Include relevant context in log messages (e.g., file paths, item IDs, stack traces).
- Do not swallow exceptions unless explicitly intended.

### Asynchronous Code
- Use `async`/`await` for I/O‑bound operations.
- Return `Task` or `Task<T>` from async methods; avoid `void`.
- Configure `await` with `ConfigureAwait(false)` where appropriate.

### Comments and Documentation
- Use XML documentation comments (`///`) for public APIs, classes, methods, and properties.
- Chinese comments are acceptable (the existing codebase uses them).
- Keep comments up‑to‑date; delete obsolete comments.
- Use `//` for inline comments sparingly, only to explain non‑obvious logic.

### Formatting
- Indent with **4 spaces** (no tabs).
- Place opening braces on the same line.
- Use blank lines to separate logical sections within a method.
- Keep lines under 120 characters; wrap when necessary.

### Dependency Injection
- The project uses SPTarkov’s DI system.
- Annotate injectable classes with `[Injectable]`.
- Specify `InjectionType` and `TypePriority` when needed.
- Constructor injection is the primary method; avoid service‑location patterns.

### Logging
- Use `LocalLog.Logger` (SuntionCore.dll提供的静态日志属性，用于记录日志到文件)。
- Choose the appropriate log level:
  - `Debug`: detailed information for development.
  - `Info`: normal operational events.
  - `Warn`: unusual but recoverable situations.
  - `Error`: errors that affect functionality.
- Include structured data in logs (e.g., `$"Item {id} created"`).

## Ignored Directories

The following directories contain autogenerated content, cached data, or documentation and **should be ignored** during code exploration and modifications:

- `Classification/`
- `IgnoreCache/`
- `Wiki/site/`

Do not read, edit, or commit changes inside these folders unless explicitly requested.

## Additional Notes

- The mod loads data files with extensions `.sic`, `.sic.json`, or `.sic.jsonc` from the `data/` folder.
- When adding new item types, extend the `SicType` enum and update `DataLoader.DeserializeBasedOnType`.
